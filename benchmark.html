01 / BENCHMARK · PROTOCOL WRITTEN FIRST · 2026-11-10

8 REAL BUG FIXES.
96 PAID RUNS.

2026-11-14: the same 8 tasks were run again with the current generator, 96 more paid runs on tasks the generator was tuned on. The default export used fewer tokens than no harness; cost and tasks solved showed no clear difference. Results and limits are on the Value page. This page describes the 2026-11-10 run.

We ran Claude Code on 8 real bug fixes from public repositories, with and without a harness generated by Olivium, and graded each patch with the tests from the real fix. Accuracy was the same in every setup; after a fix, cost showed no measurable difference.

The first run found that it cost more, because its own permission settings refused 35 ordinary calls. After a fix, cost per solved task is $0.0935 against $0.0917 for Claude Code's /init and $0.0827 for no instruction file; the paired per-task difference shows no clear difference against either. Accuracy was equal in every setup.

This benchmark tested the harness before its lean settings existed. Tests on development tasks since then are in Later tests: the one large saving there is a settings change any user could make by hand, and there is no held-out result for it yet.

02 / HOW IT WORKS

[ 01 / SELECT ]

Task selection by rule

Merged pull requests that close a linked issue, change at most 3 non-test files and 100 non-test lines, and add or change a test. Each is checked in Docker: tests fail at the base commit and pass with the real fix, 3 of 3 times.

corpus/manifest-v2.json1,877 rejections recorded

What happens

Tasks are merged pull requests from public MIT/BSD/Apache-2.0 repositories in Python or JavaScript/TypeScript, merged after 2026-06-30, newest first. The pull request must close a linked issue in the same repository with a prose description (at least 20 words, issue at most 365 days old), change at most 3 non-test files and 100 non-test lines, add or change at least one test file, and touch no dependency manifest. Each candidate is validated in Docker with no network: target tests fail at the base commit with the test patch applied and pass with the real fix, 3 of 3 times each, within 300 s. Result: the 5 pilot tasks (click x2, flask, attrs, express) plus 3 held-out tasks, all from pallets/werkzeug. The rule aimed for 5 held-out tasks and found 3 (the minimum allowed).

What keeps it fair

Nobody picks a task by hand. Every rejected candidate is recorded with its reason (1,877 rows in rejected-v2.jsonl). The manifest is frozen with a checksum (c8bde114...) before any paid run. The repository stores references only: URLs, commit SHAs and the SHA-256 of the issue text.

[ 02 / MATERIALIZE ]

Materialization at the base commit

Each task is rebuilt at the commit before the fix. The generator gets a git repository holding only that commit and its ancestors: no tags, no remote, no fix.

corpus/materialize.pyarms/olivium_v2.pyHEAD == base_sha

What happens

materialize.py rebuilds each task in a scratch directory from the manifest: issue.md (re-fetched and checked against issue_sha256), test.patch, gold.patch and repo/ (the tree at base_sha, the commit before the fix). For the generator, a fresh local git repository is built per task holding only base_sha and its ancestors: branch main only, no tags, no remote, reflogs expired, unreachable objects pruned.

What keeps it fair

A check before the arm is accepted: HEAD equals base_sha; the fix commit and every pull-request commit are absent; no exported file contains the fix SHA, a PR commit SHA (full or 12-character prefix) or the PR number as #NNNN. A failure stops the benchmark.

[ 03 / SETUPS ]

Three setups (arms)

The same snapshot three ways: no instruction file, a CLAUDE.md from Claude Code's own /init, or the unmodified Olivium export. Instruction files shipped with the repository are removed first.

arms/entry.sharms/olivium_v2.py

What happens

none: the repository at the base commit, no instruction file. generic: the same plus a CLAUDE.md written by Claude Code's own /init at that commit, through the meter (cost $0.4557 for 8 tasks, reported separately as setup). olivium: the same plus the unmodified output of bin/harnessforge generate PATH --runtime claude_code --export DIR --json: CLAUDE.md, .claude/settings.json, the hook scripts under .claude/hooks/ and .olivium/*. The generator parses repository files and git history, runs nothing from the repository and calls no model (setup $0).

What keeps it fair

Every setup starts from the same snapshot. entry.sh first removes any CLAUDE.md, AGENTS.md, copilot-instructions.md, .claude or .cursor shipped with the repository, at any depth. Before the agent starts it records the SHA-256 of every harness file and of the --settings file; the runner compares them with the arm's files and scores the trial infra_error on any mismatch.

[ 04 / AGENT ]

Agent container

Headless Claude Code with the issue text as the prompt. Limits: 60 turns, 1200 s, $3 per run. The container sits on an internal network whose only peer is the meter, and holds a dummy API key.

lib/session.py--disallowedTools WebSearch,WebFetch

What happens

Each run is one headless Claude Code 2.1.311 session (claude -p --output-format stream-json) with model claude-sonnet-5-5 in its own Docker container, created from a per-task image, files copied in with docker cp, no host mounts. Limits: 60 main-session turns, 1200 s (20 minutes), $3 per run; container limits 1500m memory, 2 CPUs, 512 processes. The container is on an internal Docker network whose only peer is the meter; it holds a dummy API key. The prompt is the issue title and body followed by 'Fix this issue in the repository in the current directory.'

What keeps it fair

Same image, prompt, model, limits and UV_NO_SYNC=1 in every setup. WebSearch and WebFetch are removed in every setup and in /init (--disallowedTools), because a search runs on the API side, past the container's isolation, and could find the upstream fix. Permission modes differ on purpose: none and generic run with bypassPermissions and one shared benchmark settings file; olivium runs its exported settings byte for byte (--settings) in default mode with no bypass, so a call its own rules refuse counts against it.

[ 05 / METER ]

Metering proxy

A reverse proxy to the model API. It alone holds the API key, attributes every request to its run, prices the tokens from a price table and enforces a per-run cap and a total cap. It stops forwarding on anything it cannot price.

meter/meter.py--refuse-web-tools

What happens

The meter is a reverse proxy to the Anthropic Messages API. It alone holds the API key, injects it when forwarding, attributes each request to its run id (/run/<run_id>/...), reads token usage from the API responses and prices it from a price table (claude-sonnet-5-5: $2 input, $10 output, $2.50 5-minute cache write, $0.10 cache read per million tokens). It enforces a per-run cap and a total cap and appends every request to requests.jsonl. The default mode is a mock model that contacts no API.

What keeps it fair

Fail-closed: an unknown model, an unwritable log or a 200 response without readable usage stops forwarding. With --refuse-web-tools it refuses any request that offers a web search or fetch server tool. The log never holds headers, bodies or the key. In the first run the meter's cost equalled Claude Code's own total_cost_usd on every trial (0 mismatches above one millionth); 501 meter rows, all live, none offering a web or server tool.

[ 06 / GRADE ]

Grading with hidden tests

The patch is applied to a clean checkout in a fresh container with no network. Test files and test configuration the agent touched are restored, then the real tests from the pull request run. Solved means every target test passes and nothing regresses.

grade/grade.sh--network none

What happens

The agent's patch is extracted (excluding CLAUDE.md, .claude/ and .olivium/) and applied to a clean checkout at the base commit in a fresh container started with --network none. Every test file, test configuration, lint configuration and CI file the agent touched is then restored or removed, the real test patch from the pull request is applied, and lint and the tests run. Solved means every fail-to-pass test passes and no pass-to-pass test regresses; the repository's linter result is recorded separately.

What keeps it fair

The agent never sees the real test patch. Restoring test files and configuration means an agent cannot pass by weakening the tests; root-level modules that could shadow the test runner are also restored. A run that hits a limit is scored unsolved and its cost counts. Stated gap: forgery through ordinary source files in the package under test is not detected.

File or flag

bench/value/grade/grade.sh (container started with --network none)

Where it is written down

[ 07 / ANALYZE ]

Analysis

For each task the 3 repeats of a setup are averaged. The difference is Olivium minus the other setup. Reported: the median across tasks with a 95% bootstrap interval (10,000 resamples). An interval that includes zero is reported as no clear difference.

analyze.pyseed 20261108

What happens

Three questions: fewer tokens and lower cost; better context (files read outside the real fix, turns and tool calls before the first edit to a file the real fix changed); more accurate (solved, regressions, lint). For each task the 3 repeats of each setup are averaged. The difference is olivium minus the other setup for that task. The headline is the median of those differences across tasks, with a 95% percentile bootstrap interval: tasks resampled with replacement 10,000 times, seed 20261108. Cost per solved task is the setup's total cost divided by its solved runs and has no interval.

What keeps it fair

An interval that includes zero is reported as no clear difference. Held-out tasks are also reported separately. Every report section carries the line: '8 tasks, one model, one agent. This can show a direction or a problem. It cannot prove a general effect.' Numbers reach other documents only from results.json.

04 / THE REFUSAL FIX

THE HARNESS REFUSED
ITS OWN AGENT.

The first run showed a defect in the product, not a benefit. This is what was refused, what changed, and how the change was checked before paying for a re-run.

  1. 01

    What the first run found

    The exported permission settings refused 35 calls in 14 of 24 runs. All were ordinary steps of working on the task; 8 of them named a path outside the repository (7 scratch files under /tmp, 1 listing under the home directory). The two baselines run with permission checks bypassed and had none.
    26
    Claude Code asked about a command no allow rule matched. An unattended session refuses.
    7
    guard hook: scratch files under /tmp
    1 + 1
    guard hook: ls ~/.local/share/uv/python and rm -rf scratch_tmp

    Source: supplement.json (source file, opens in a new tab), report.md, first run (source file, opens in a new tab)

  2. 02

    Change 1: allow the shell in solo mode

    In solo mode, the unattended default, the export's allow list gains a plain Bash rule, so Claude Code does not ask before a shell command such as cd dir && git ... or sed -i. Deny rules and the guard hook are still checked first and still refuse.
  3. 03

    Change 2: scratch files in /tmp

    The guard no longer counts the system's scratch directories as outside the project. A secret file name there, or a link from there to somewhere else, is still refused.
  4. 04

    A caution from the report

    Runs with a refusal: 14, mean cost $0.0778, mean 9.5 turns. Runs without: 10, mean cost $0.0630, mean 5.6 turns. Refusals are not assigned at random, so this split does not by itself show that refusals caused the cost difference.

What still refuses the fix widened what runs; it did not remove the deny rules

06 / LIMITS

WHAT THIS
CANNOT SHOW.

8 tasks, one model, one agent. This can show a direction or a problem. It cannot prove a general effect.

  • Small and narrow. 8 bug fixes, 7 in Python and 1 in JavaScript, one model (claude-sonnet-5-5) and one agent (Claude Code 2.1.311).
  • The after-fix run is not a held-out result. It uses the same tasks the fix was found on.
  • Two runs, a few hours apart. The after-fix comparison sets re-run Olivium trials against the first run's baselines, which were not re-run.
  • Accuracy did not move. Each task was solved by all its runs or by none, in every setup: 5 always, 3 never.
  • Tuning overlap. The analyzer was tuned while looking at four of the repositories at the same base commits. Only the 3 held-out tasks are free of that overlap, and all 3 come from one repository, pallets/werkzeug. The rule aimed for 5 held-out tasks and found 3. werkzeug shares its owner, layout and tooling conventions with click and flask, which the analyzer was tuned on, so the held-out tasks are free of the base-commit overlap but not of that family resemblance.
  • Held-out tasks still lean costlier. After the fix, on those 3 tasks: +$0.0078 (-$0.0011 to +$0.0158) against no file and +$0.0061 (-$0.0033 to +$0.0094) against /init. Both intervals include zero.
  • Unequal permission modes. The baselines run with permission checks bypassed; the harness runs its own settings. That is the registered design, so refusals count against the harness only.
  • Context measures are a lower bound. Files read through grep, rg, find or an interpreter are not counted as reads.
  • A stated grading gap. Forgery through ordinary source files in the package under test is not detected.
  • The harness was already changed once before the first run. A paid canary on click #3858 found 5 refused calls; the generator's allow list was widened and the guard hook added before any scored run. The canary is not scored. Source: PROTOCOL-v2.md, change log (source file, opens in a new tab), provenance.json, first run (source file, opens in a new tab)
  • The earlier pilot is not comparable. It measured an older harness with exported settings unused and web tools offered. It is a different run, not a before and after.
