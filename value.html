What Olivium Harness gives you / measured 2026-11-10 to 2026-11-14

It reads a git repository and writes a harness for Claude Code.

The harness is CLAUDE.md, a settings file, three hooks, and skills and subagents built from the repository's git history. The generator calls no model. The same commit gives the same files.

$ bin/harnessforge generate /absolute/path/to/your/repo \ --runtime claude_code --export /absolute/path/to/new-directory

Latest measurement, 2026-11-14: on the 8 benchmark tasks, 24 paid runs per setup, the default export used a median of 53,197 fewer tokens per run than no harness (95% interval 16,825 to 72,241 fewer). Cost per run and tasks solved showed no clear difference.

Limits: the generator was tuned on these 8 tasks, so this is not a held-out result. Generated skills were called in 6 of 24 runs and subagents never; the same export without them used the fewest tokens. In an earlier test the lean settings alone, without generated files, gave 0.37x the tokens of no harness; you could set them by hand. There is no held-out result yet.

What you get

generate writes into a new directory and refuses one that already exists. Exit status is 0 on success, 1 on failure, 2 on a usage error and 3 for an unsupported runtime or mode.

Sizes are bytes on disk in the golden Python export from the test suite. That fixture has too little history for skills or subagents, so their figures come from real exports of public repositories.

  • ./export root
  • ├─ CLAUDE.md285 B

    At most 600 bytes. Only lines the agent cannot guess. Each line left out is listed with a reason in .olivium/guidance-provenance.json. On the 8 benchmark tasks: 72 to 404 bytes, 4 to 15 lines withheld.

  • ├─ .claude/settings.json4,534 B

    48 allow rules including bare Bash, 118 deny, 0 ask. defaultMode: default, includeGitInstructions: false, disableSkillShellExecution: true.

  • ├─ .claude/hooks/olivium-guard.sh38,854 B

    PreToolUse. Only refuses, never approves. Runs only while its SHA-256 equals the generated value. PATH=/usr/bin:/bin, 10 s timeout.

  • ├─ .claude/hooks/olivium-before-stop.sh11,285 B

    Stop. Formats and lints changed files and runs only changed test files, at most 3, 60 s per step. Silent unless a check fails; then it blocks the stop once with at most 1,200 characters.

  • ├─ .claude/hooks/olivium-env-check.sh1,566 B

    SessionStart. Prints one line per listed tool that is not installed, nothing when all resolve. When it fires it adds 44 tokens to the first request.

  • ├─ .claude/skills/olivium-area-<name>/SKILL.mdfrom history, 0 to 3

    Files that change together, their tests and past fixes. sqlite-utils: 188 B listed on every request, 1,165 B loaded when the skill is called.

  • ├─ .claude/agents/olivium-locator.mdfrom history

    Read-only search with Read, Grep, Glob. Replies with at most 15 path:start-end - reason lines, no file contents.

  • └─ .claude/agents/olivium-test-runner.mdfrom history

    Runs only the detected test command with Bash, Read. Replies PASS <count> or the failing tests with their first error lines, 60 lines at most.

  • └─ .olivium/records

    What was generated and from what: spec, provenance, capability report, manifest. native-provenance.json lists each skill's and subagent's evidence commits, sizes, sha256, cost estimate, and dropped items with reasons.

Real generated files

Verbatim, generated 2026-11-13 with the default --native all. Only paths, commands, commit hashes and counts come from the repository. The rest is a fixed English template. No commit message is copied. Lines in purple brackets are omitted here and are not part of the file.

Historygit log, no model

How it learns from history

Co-change groups
At least 2 source files changed together in at least 4 focused commits of 2 to 25 files. Formatting, lint, version-support drops, migrations, bumps, and style, chore, ci, build and docs commits do not count. Renames are followed.
History-paired tests
Test files that changed with those sources, each with the command that runs it.
Fix commits
Up to 5 per area, with the files each changed. Only the hash is written, so a model needs git show to learn what a fix did.
Reverts and follow-ups
Files reverted or fixed again within 7 days.
The repository's own rules
Up to 2 rules from its own instruction files that name one of the area's files, each at most 240 bytes.

Gates. An item is written only when its gate passes. The gates are a judgment, not a measurement.

ItemWritten when
Area skill, 0 to 3A co-change group as above.
Locator subagentAt least 40 source files and a co-change group strong enough for an area skill.
Test-runner subagentAt least 3 history-paired tests and a command that runs one test file (pytest, not npm run ...).
Any of themAt least 200 commits of history. A shallow clone with fewer gets none and is told to run git fetch --unshallow. generate never fetches.

Every item cites its evidence commits, all at or before the commit it was generated from, in .olivium/native-provenance.json. Size limits: listing at most 1,200 bytes, description at most 200 bytes, each skill or agent body at most 2,048 bytes.

--native all|skills|agents|none picks what is written. The default is all; a bad value exits 2. Settings gain one Skill(olivium-area-<name>) allow rule per generated skill, never bare Skill. No skill has allowed-tools. Forged log records, ---, backticks and $(...) in commit subjects, and quotes, newlines or @ in file names reach no export (end-to-end check C25).

Optional AI step. harnessforge learn with --context lean-ai lets a model read the history and propose skills and subagents as paths, commit hashes and command ids, never free text. The same templates render them, and a test runner keeps only commands that ran in Docker with no network. This route has run only with a scripted mock learner, not with a real model.

Safetyguard and deny rules

What the settings and the guard refuse

Deny rules

rm -rrm -rfsudocurlwgetsshghgit fetchgit pullgit clonegit pushgit reset --hardgit cleangit rebasecat .env

Also publish commands and edits to secret file patterns. A real export (sqlite-utils) has 115 deny, 49 allow and 0 ask rules. git commit is allowed because a local commit can be undone; git push and gh stay denied.

Claude Code enforces these without the guard. With the guard file deleted and plain Bash allowed, it refused 9 of 9 dangerous commands. That test ran while git commit was still denied.

The guard only takes calls away

In the $0 replay: 142 PreToolUse responses, 0 approvals, 0 nonzero exits. Over 1,099 calls run with and without it, no call ran with the full export that did not also run with the rules alone.

Refusals in paid runs: 35 in 14 of 24 runs before the fix, 4 in 4 of 24 after. All 4 came from the guard, on purpose: one home-directory listing and three package-registry fetches.

In 4 unsafe cases a different layer refused than the list expected; all 4 were still refused. The list includes 12 test-runner entries.

  • Not a sandbox. An allowed interpreter or test runner runs with your rights. Run unattended sessions in a container or VM.
  • Known gap. A program the agent runs can rewrite .claude/settings.local.json. The guard sees sed, tee and redirect writes, not a python3 or node write.
  • Trust. In an untrusted workspace Claude Code ignores the exported allow rules.
Not proven

What is not proven

  • No held-out result. No lean profile has one. The held-out pilot stopped with 2 usable tasks of 24, against a floor of 12.
  • The one large saving is settings you can set by hand. includeGitInstructions: false and 15 tool denies: 0.37x alone, 0.39x with the full export. 8 tasks the generator was tuned on, 16 runs per setup, no interval.
  • The generated CLAUDE.md and hooks did not cut tokens or raise solves beyond the settings in any test so far.
  • Skills and subagents show no measured effect. One paid A/B run on 8 development tasks (2026-11-14): skills were called in 6 of 24 runs, all on tasks no setup solved, and subagents never; no difference in tokens, cost or solved share could be told from zero. Whether they help when used, or on other repositories, is not measured. Their cost is estimated at +3,544 to +3,624 tokens per request on three real repositories; the estimate matched a live capture on the synthetic repository (3,625 measured against 3,624). Each subagent turn adds about 3,472 to 4,582 tokens of its own, also estimated from bytes.
  • Their content is mechanical. Paths, test pairs and bare fix hashes. A review before the last repair rated it partly useful; on full history about half of the content was wrong or noise. The repair fixed the listed blockers. It does not add commit subjects.
  • Some repositories get nothing. jsonschema gets no skill or subagent even with full history. mocha gets none from a shallow clone.
  • Not verified. Whether maxTurns is enforced. The per-name Skill(<name>) rule is verified live for one skill on the synthetic fixture only. The learned route ran only with a scripted mock learner.
  • One model, one agent. claude-sonnet-5-5 and Claude Code 2.1.311. Tool names and byte costs are specific to that version.
  • lean turns off your own skills and subagents in that project, unless the repository has its own .claude/agents or .claude/skills. Then they are kept and the saving is reported as not measured.
