OPEN-SOURCE HARNESS GENERATOR

A HARNESS
FOR YOUR REPO.

The harness is a set of files Claude Code loads: CLAUDE.md, settings and hooks.

The settings hold allow and deny rules. A guard hook only refuses; two more hooks format files and run checks before the agent stops. The generator makes no model calls, and the same input gives the same files. Team knowledge is added as claims that a person reviews and approves.

SOURCES, REVIEW,

A harness is the context around your coding agent: instructions to follow, workflows to use, and checks to perform. HOW IT IS MEASURED /

The design was written in bench/value/PROTOCOL-v2.md before any run of this version. 5 tasks were carried over from an earlier pilot; 3 held-out tasks were selected afterwards.

  1. 01

    SELECT

    8 merged bug-fix pull requests from public repositories, chosen by a written rule.

    bench/value/corpus/manifest-v2.json
  2. 02

    ISOLATE

    One Docker container per run, built at the commit before the fix. No host mounts.

    bench/value/run.py
  3. 03

    METER

    A proxy holds the API key and records tokens and cost for every request.

    bench/value/meter/meter.py
  4. 04

    GRADE

    The patch is applied to a clean checkout and run against the tests from the real fix, without network.

    bench/value/grade/grade.sh
  5. 05

    PAIR

    Per-task differences, Olivium minus baseline, with a 95% bootstrap interval.

    bench/value/analyze.py

05 / THE DETAILS

QUESTIONS AND ANSWERS.

Scope, inputs, approval, cloud use, benchmark and status.

01 Is this another coding agent?+

No. Olivium Harness builds the instructions, settings and checks around your agent. The generator writes a Claude Code harness from a git repository. The reviewed pipeline exports approved guidance as native previews for Codex CLI, Claude Code and OpenCode.

02 What can I use as context?+

For the generator: a local git repository, its files and history. For the reviewed pipeline: selected Markdown or text documents; GitHub metadata, issues, pull-request descriptions and reviews; GitHub Projects; Jira Cloud issues; Slack threads; and Confluence Cloud pages. GitHub imports in that pipeline do not currently ingest repository source files. Current cross-source analysis uses two to four selected documents and one saved goal.

03 Who approves the instructions?+

You do. Recommendations include supporting evidence for review. You can edit, reject, and resolve conflicts before approving an exact revision. The package plan requires a separate approval before the harness is built.

04 Does local-first mean no cloud AI?+

Cloud AI is optional. If you choose a cloud model provider, selected context can leave your machine with your consent. Provider access and spending are controlled explicitly.

05 Does the harness make the agent better?+

Not measurably, in the one benchmark so far (one model, one agent, a first run and a re-run after a fix). On 8 real bug-fix tasks with claude-sonnet-5-5 and Claude Code 2.1.311, the agent solved 15 of 24 runs with no instruction file, with Claude Code’s /init, and with an Olivium harness. The first run cost more, because the harness’s own permission settings refused 35 ordinary calls. After a fix there is no clear cost difference against either baseline. Eight tasks, one model and one agent can show a direction or a problem; they cannot prove a general effect. Read the benchmark.

06 What is the project’s current status?+

Olivium Harness is an open-source tool under Apache 2.0, in active development. The source is on GitHub, linked in the footer. A public product release is not yet available. The animations on this page are illustrative. Export support is separate from validation of an agent’s live runtime.
